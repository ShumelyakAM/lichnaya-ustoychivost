# Содержание сайта

Статьи редактируются в [Pages CMS](https://app.pagescms.org/) в разделе «Статьи блога». Каждая статья хранится в отдельном файле `articles/<slug>.json`: заголовок, тема, дата, описание для поиска и текст находятся в одной записи. При создании статьи задайте короткий адрес латиницей; после публикации не меняйте его, чтобы ссылки продолжали работать.

Раздел «Цифровые продукты» в Pages CMS редактирует `products.json`. Для нового продукта заполните название, описание, формат и состав, включите «Показывать в каталоге». Если у него уже есть отдельная страница, укажите `landing` с адресом внутри сайта. Иначе сборщик создаст страницу по общему шаблону. Не добавляйте цену, дату старта или обещания результата без утверждённого решения.

Раздел «Программа „Личная устойчивость“» редактирует пять модулей из `program.json`. Сверяйте изменения с утверждённой программой курса. Остальной текст подробной страницы пока редактируется в `index.html` репозитория; сборщик сохраняет его и обновляет только блок модулей, навигацию и метаданные.

После сохранения в Pages CMS изменение попадает в GitHub. Workflow `.github/workflows/pages.yml` собирает сайт и публикует готовые страницы. В настройках GitHub Pages источником публикации должен быть **GitHub Actions**.

Команда сборки из корня проекта:

```text
python tools/build_site.py
python tools/check_site.py
```

Для локальной сборки нужен Python с библиотекой `lxml`. Готовые страницы репозитория лежат в корне; после изменений через Pages CMS локально запускать сборку не требуется.
